# 资源维护指南

## 新增教学资源

1. 选择 `学期课程/学期/课程名/`，新课程先建立课程 README。
2. 课程标准与授课计划分别存入同名目录；按教学周次使用 `第01周`、`第02周` 等补零名称。
3. 周目录下按实际需要使用 `教案`、`课件`、`参考资料`、`代码与实验`、`数据与练习`、`素材`、`配套资料`。
4. 保留有意义的原文件名，优先包含周次、课次和主题；不要将同一份文件重复上传到根目录。
5. 完整代码项目按项目存放，保留 `data`、图片、UI、依赖及原许可证之间的相对路径。
6. 更新课程 README、学期 README 和总资源清单。

## 专题与大文件

- 不专属于某一学期的资料放在 `专题资源/主题/`。
- 同内容的 Office/PDF 文档可只保留一份，并在课程索引提供链接。
- 超过 50 MB 的单文件和体积较大的 RAR 教程包使用 GitHub Releases 分发，在相关目录 README 与“[大文件下载](大文件下载.md)”登记下载链接、原文件名、大小和 SHA-256。
- 如调整 Releases 附件名称或版本标签，需同步修正文档中的下载链接。

## 发布前检查

- 文档能打开，标题、周次、学期与课程归类相符。
- 公开范围涵盖所上传内容；内部教务、个人联系方式、账号密钥和非公开学生记录留在本地。
- 第三方来源、原作者说明与许可证随资料保留。
- 更新后的目录链接可用，下载附件与记录的哈希一致。
- 说明实验代码是否已经实际运行，不把文件整理验证描述成运行测试通过。

## 当前索引字段

`docs/资源清单.csv` 包含来源学期、分类、课程或专题、资源类型、原相对路径、整理后路径、实际存储路径、字节数、SHA-256 及下载链接。

如同一份文档出现在多个原始目录，清单保留每条来源记录，实际存储路径可指向同一文件。
